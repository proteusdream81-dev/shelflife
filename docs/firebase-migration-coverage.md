The viewer UID always comes from the verified Firebase bearer token; the target reader UID is a validated path parameter. Both profiles must have independently verified forward/reverse legacy identity links.

## 12 November 2026 — Reading Circle overview endpoint

- Added authenticated `GET /api/relationships?overview=true` and the Firebase client adapter `getOverview`. The endpoint preserves the legacy response arrays: `following`, `followers`, `suggested`, `requests`, `requested` and `blocked`. The viewer UID is derived from the verified Firebase bearer token; every returned profile is checked against matching verified forward/reverse legacy identity links.
- Following, follower, incoming-request and outgoing-request projections exclude readers blocked in either direction. The `blocked` list contains the viewer's own blocks. Suggestions are derived only from shared, non-private, non-selected shelves and exclude connected, blocked, hidden and unlinked readers. `shared_shelves` counts exclude private and selected-recipient shelves. The overview uses the 150 reads/hour `readingCircleRead` cap.
- Queries are bounded: at most 100 following records, 100 follower records, 100 blocks per direction and 300 shared shelf documents. If a collection exceeds its safe bound, the endpoint returns a conflict rather than silently truncating the overview.
- Regression tests cover relationship direction/status, reciprocal follow state, shared-shelf counts, hidden/blocked/unlinked exclusion, suggestions, handler rate limiting and route selection for overview, name and username-availability requests.
- This closes the Reading Circle shared-reader library and overview API slices. The active Friends, ReaderLibrary, FollowersCard, InviteReadersCard and SharePanel UI still use Base44; no app-wide Firebase AuthContext or UI cutover has been made.
